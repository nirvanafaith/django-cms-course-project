# Django CMS 前端技术架构小白教案

> 阅读范围：本篇只根据 `cms_site/templates/`、`cms_site/static/` 与后端视图传入模板的数据来解释前端。它不把项目当作 React、Vue 或前后端分离应用，而是解释实际存在的 Django 服务端渲染页面。

## 1. 先用一句话认识这个前端

这个网站使用的是 **服务端渲染（Server-Side Rendering，SSR）**：

```text
浏览器请求一个网址
  -> Django 在服务器查询文章和栏目
  -> Django 把数据填进 HTML 模板
  -> 浏览器收到已经包含正文的 HTML
  -> CSS 负责样式
  -> 少量原生 JavaScript 负责菜单和轮播交互
```

因此，浏览器不是先下载一个大型 JavaScript 应用，再向 API 请求文章数据；文章标题、正文、搜索结果等主要内容在服务器端已经生成。`static/js/main.js` 只为已存在页面补充移动菜单和轮播功能。

这种做法常被称为 **渐进增强（Progressive Enhancement）**：即使 JavaScript 没有加载，用户仍可以阅读内容、访问链接和提交搜索表单；JavaScript 加载后，体验会更方便。

## 2. 前端文件怎样分工

```text
cms_site/
├── templates/                     Django HTML 模板
│   ├── base.html                  每页共同的骨架
│   ├── partials/                  导航、消息等可复用 HTML 小部件
│   ├── content/                   首页、详情、搜索结果等内容页面
│   ├── registration/              登录页面
│   └── 400.html ... 500.html      错误页面
└── static/                        不由模板直接生成的静态资源
    ├── css/                       颜色、布局、响应式样式
    ├── js/main.js                 交互增强脚本
    └── img/                       图片、图标和素材
```

可以把模板理解成带空位的 HTML 设计图，CSS 理解成装修规则，JavaScript 理解成少量交互开关。

## 3. `base.html`：所有页面共用的母版

入口是 `cms_site/templates/base.html`。它规定了网页反复出现的结构：

```text
<html>
  <head> CSS、标题、移动端 viewport、静态资源 </head>
  <body>
    导航栏
    主内容区
    页脚
    JavaScript
  </body>
</html>
```

### 3.1 模板继承是什么

Django 模板中的：

```django
{% block content %}{% endblock %}
```

是一个可替换区域。子页面通常写：

```django
{% extends "base.html" %}
{% block content %}
  <!-- 本页独有内容 -->
{% endblock %}
```

这叫 **模板继承**。它避免每一个页面都复制导航、页脚、CSS 链接和脚本链接。

### 3.2 `{% load static %}` 和静态资源

`base.html` 顶部的：

```django
{% load static %}
```

启用了 Django 的静态文件模板标签。随后：

```django
{% static 'css/custom.css' %}
```

会由 Django 根据运行环境生成正确静态资源地址。开发者不必在每个模板里手工猜 `/static/` 的绝对路径，也能让生产环境的静态文件版本管理正常工作。

### 3.3 `include`：将重复片段拆出来

页面使用：

```django
{% include "partials/nav.html" %}
```

把导航栏嵌入进来。`include` 适合“已经是完整小片段、多个页面都需要”的内容，例如导航、消息提示和分页器。

### 3.4 模板上下文从哪里来

后端视图调用：

```python
render(request, "content/index.html", context)
```

其中 `context` 是 Python 字典。字典中的：

```python
{"page_title": "首页", "latest_items": items}
```

在模板里会变成：

```django
{{ page_title }}
{% for item in latest_items %}
```

所以模板不自己连接数据库；它只显示后端已经准备好的数据。

## 4. HTML：页面的语义骨架

HTML 不只是“显示文字的标签”。合理标签还能帮助屏幕阅读器、搜索引擎、键盘用户和维护者理解页面。

项目中常见的结构包括：

- `<nav>`：导航区域。
- `<main id="main-content">`：页面主要内容。
- `<article>`：一篇文章的独立内容。
- `<header>`、`<footer>`：页头与页脚。
- `<form>`：搜索和登录输入区域。
- `<button>`：触发动作，例如展开菜单、切换轮播。
- `<details>` 与 `<summary>`：浏览器原生可展开信息块。

`base.html` 的 `main` 有 `id="main-content"`，这让“跳到主要内容”的无障碍链接可以把焦点直接送到正文，而不是要求键盘用户每次都穿过导航。

## 5. CSS：从设计变量到页面布局

CSS（Cascading Style Sheets，层叠样式表）负责视觉呈现，不负责查询文章数据。

项目将样式拆成多个责任清楚的文件：

```text
css/tokens.css       颜色、间距、字号等设计变量
css/custom.css       全局基础样式和通用组件
css/chrome.css       站点框架，例如导航和页脚
css/home.css         首页专属布局
css/content.css      文章、搜索、分页等内容页样式
css/responsive.css   小屏幕与减少动画偏好
```

### 5.1 设计变量

项目用 CSS 自定义属性统一管理视觉常量，例如：

```css
color: var(--bjtu-blue);
padding: var(--bjtu-space-4);
```

`var(...)` 的值来自设计变量。这样修改主色或间距尺度时，通常只需调整变量定义，而不是全项目搜索替换颜色值。

### 5.2 `box-sizing: border-box`

`custom.css` 为所有元素设置：

```css
* { box-sizing: border-box; }
```

默认的 `content-box` 中，声明 `width: 100px` 后，padding 和 border 会额外增加元素实际宽度。`border-box` 则让声明的宽度包含内容、内边距和边框，更适合响应式页面计算尺寸。

### 5.3 容器和自适应宽度

`.bjtu-container` 使用：

```css
width: min(calc(100% - var(--bjtu-space-8)), var(--bjtu-content-max));
margin-inline: auto;
```

含义是：

1. 页面在小屏幕上保留左右边距。
2. 页面在大屏幕上不无限拉宽。
3. `margin-inline: auto` 让内容在水平方向居中。

这是内容型网站常用的阅读宽度控制方式。

### 5.4 Flexbox 和 Grid

项目用 **Flexbox** 排列一维项目，例如标题在左、更多链接在右：

```css
.section-heading {
  display: flex;
  justify-content: space-between;
}
```

它也用 **CSS Grid** 让错误页内容垂直和水平居中：

```css
.error-page {
  display: grid;
  place-items: center;
}
```

简单记忆：一排或一列优先考虑 Flexbox；需要二维布局或方便的整体对齐时考虑 Grid。

### 5.5 可访问性样式

`:focus-visible` 用于键盘焦点：

```css
:focus-visible {
  outline: 3px solid var(--bjtu-gold);
}
```

鼠标点击不一定需要明显焦点框，但键盘按 Tab 导航时必须知道当前焦点在哪。移除 `outline` 会让键盘用户迷路，因此这里保留清晰轮廓。

`.visually-hidden` 让文字在视觉上隐藏、但屏幕阅读器仍能读到。它适合轮播状态、补充标题等无障碍信息，不应用来隐藏真正重要的页面内容。

## 6. JavaScript：只做交互增强

唯一运行脚本是 `cms_site/static/js/main.js`。它使用原生浏览器 API，不依赖 jQuery、React 或其他前端框架。

文件最外层是：

```js
(() => {
  "use strict";
  // 代码
})();
```

这叫 **立即执行函数表达式（IIFE）**：定义后立刻运行，并把变量关在自己的作用域中，避免污染全局 `window`。

### 6.1 DOM 查询

```js
document.querySelector("[data-nav-toggle]");
document.querySelectorAll("[data-carousel]");
```

DOM 是浏览器把 HTML 解析成的对象树。`querySelector` 找第一个匹配元素；`querySelectorAll` 找到一组元素。

这里使用 `data-*` 属性作为 JavaScript 钩子，例如 `data-carousel`。它比用纯视觉 class 绑定脚本更清楚：class 可以表示外观，data 属性表示行为。

### 6.2 移动端导航菜单

菜单按钮的状态通过：

```js
aria-expanded="true"
```

告诉辅助技术“菜单已展开”。脚本切换：

- 按钮的 `aria-expanded`。
- 按钮的 `aria-label` 与 `title`。
- 菜单的 `.is-open` class。

CSS 根据 `.is-open` 决定菜单是否可见。JavaScript 保存状态，CSS 负责视觉结果，这种分工比直接在脚本中拼大量样式更清楚。

脚本还监听 `Escape`：用户按 Esc 会关闭菜单。这是常见键盘交互约定。

### 6.3 轮播组件

每个 `[data-carousel]` 都有独立状态：

```js
let activeIndex = 0;
let paused = reduceMotion.matches;
let timerId = null;
```

- `activeIndex`：正在显示第几张。
- `paused`：是否暂停自动播放。
- `timerId`：浏览器定时器编号。

`renderSlide()` 把状态同步到 DOM：

```js
slide.classList.toggle("is-active", active);
slide.setAttribute("aria-hidden", String(!active));
```

第一行决定样式，第二行告诉屏幕阅读器非当前图片应视为隐藏。

自动播放使用：

```js
window.setInterval(..., 6000);
```

每 6 秒切换一次。启动新定时器前调用 `clearInterval`，避免同一个轮播累计多个定时器而越播越快。

### 6.4 尊重减少动画偏好

```js
window.matchMedia("(prefers-reduced-motion: reduce)");
```

浏览器会读取用户系统的“减少动态效果”偏好。若用户开启该偏好，轮播默认暂停。这不是装饰性细节，而是让晕动症、注意力障碍或偏好静态内容的用户能更舒适地浏览。

### 6.5 键盘轮播控制

轮播支持：

- 左箭头：上一张。
- 右箭头：下一张。
- 暂停/继续按钮。

按方向键时调用 `event.preventDefault()`，阻止浏览器把方向键当成页面滚动命令。

## 7. 搜索表单不是 JavaScript 搜索

搜索页由浏览器提交普通 GET 表单，例如：

```text
/search/?q=校园&category=通知公告
```

后端的 `SearchForm` 检查输入，查询器读取数据库，模板生成结果页。这样做的好处是：

- 搜索 URL 可复制、收藏和分享。
- 刷新页面不会丢失结果。
- 不依赖 JavaScript 才能使用。
- 服务器保有输入校验和数据权限的最终控制权。

前端只负责把表单字段、错误信息和分页链接显示出来。

## 8. 静态文件如何从开发进入生产

源 CSS、JS、图片放在 `static/`。生产部署前执行：

```bash
python manage.py collectstatic
```

Django 会收集静态文件到 `STATIC_ROOT`。公网模式使用 WhiteNoise 的压缩 Manifest 存储：文件名会包含内容哈希，浏览器能长期缓存未改变的资源，而更新后的文件会获得新名字，避免用户拿到旧版本 CSS 或 JS。

Dockerfile 也在镜像构建阶段执行 `collectstatic`，说明容器启动后不需要临时再打包静态资源。

## 9. 一次完整页面请求的前端视角

以文章详情页为例：

```text
1. 用户点击文章链接 /item/12/
2. 浏览器发出 HTTP GET 请求
3. Django 查询文章并渲染 item_detail.html
4. item_detail.html 继承 base.html
5. 浏览器收到完整 HTML
6. 浏览器下载 CSS，完成排版和响应式布局
7. 浏览器下载 defer 的 main.js
8. JavaScript 为菜单和可能存在的轮播绑定事件
```

`defer` 的含义是：脚本下载可以并行，但执行会等 HTML 解析完成。这样脚本能找到页面元素，也不会阻塞浏览器先显示 HTML。

## 10. 小白常见误解

### “模板就是前端框架吗？”

不是。Django 模板是服务器端 HTML 生成工具；React/Vue 通常在浏览器内用 JavaScript 管理组件状态和 DOM 更新。两者都能生成页面，但主要运行位置和数据流不同。

### “有 JavaScript 就一定是单页应用吗？”

不是。这里的 JavaScript 不接管路由，也不拉取文章数据。用户打开新文章仍会请求新页面，所以这是多页、服务端渲染网站。

### “CSS 只关乎好看吗？”

不只。CSS 还决定阅读宽度、手机适配、焦点可见性、减少动画偏好、错误页布局和图片是否溢出。

### “前端校验能保护数据库吗？”

不能。浏览器端提示只能改善体验，用户可绕开或伪造请求。真正的输入校验、草稿过滤和权限判断必须在 Django 后端执行。

## 11. 继续阅读代码的建议顺序

1. `templates/base.html`：先理解共同页面骨架。
2. `templates/partials/nav.html`：理解导航和 `data-*` 行为钩子。
3. `templates/content/index.html`：理解首页怎样使用后端传入的文章分组。
4. `static/css/tokens.css`：理解设计变量。
5. `static/css/custom.css` 与 `responsive.css`：理解基础布局和小屏幕适配。
6. `static/js/main.js`：理解导航和轮播状态如何同步到 DOM。
7. `content/views.py`：最后回到后端，观察模板数据是怎样准备好的。

## 12. 总结

这个项目的前端架构追求的是清晰和低运行时复杂度：

```text
Django 模板     负责把服务器数据组织成 HTML
语义化 HTML     负责内容结构和可访问性
模块化 CSS      负责设计变量、布局和响应式呈现
原生 JavaScript 负责菜单和轮播等可选增强
WhiteNoise      负责生产环境静态资源服务
```

理解这条边界很重要：页面内容的真实性、权限和查询条件属于后端；页面怎样排版、怎样被浏览器交互使用属于前端。两者通过模板上下文和 HTML 表单相接，而不是通过一个复杂的前端 API 状态管理层相接。
