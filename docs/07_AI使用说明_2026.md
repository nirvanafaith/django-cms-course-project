# AI 使用说明（2026）

## 1. 使用范围

本项目在需求梳理、设计取舍、代码实现、测试设计、调试、文档结构与浏览器验收中使用 AI 辅助。使用的主要模型和工具包括 GPT-5.6 Sol / Sisyphus、sequential-thinking、Context7、CodeGraph、BasedPyright LSP、Ruff、Docker Compose 和 Playwright。

## 2. 代表性提示与人工决策

| 环节 | 代表性请求 | 采纳结果 | 人工复核 |
| --- | --- | --- | --- |
| 架构 | 将 CMS 固定为 PostgreSQL 18.6 并保留 Django Admin | 采纳单体 SSR、三张核心业务表和 Compose 部署 | 核对迁移、Compose、模型和权限 |
| 查询 | 支持题目、日期、栏目组合查询 | 采纳表单边界和 QuerySet 组合 | 运行公开内容测试与索引计划 |
| 前端 | 基于授权素材复刻学校主站信息结构 | 采纳本地素材、可访问轮播和响应式导航 | Playwright 多视口检查 |
| 文档 | 同步课程交付材料 | 采纳可执行文档合同测试 | 人工对照源码、命令和报告 |

## 3. 未采纳方案

- 不将核心业务拆成超过三张的物理业务表：课程约束要求固定 `auth_user`、`content_category`、`content_item`。
- 不创建自定义 User 模型：Django 内置 `auth.User` 已满足两种角色和 Admin 需求。
- 不重写一套自定义 CRUD 后台：保留 Django Admin 的权限、审计、筛选、删除确认和高密度操作能力。
- 不保留旧数据库后端或它的测试路径：当前运行和测试统一为 PostgreSQL 18.6。

## 4. 数据与安全边界

不向外部服务提交真实个人信息、生产密码、访问令牌、数据库备份、Cookie、日志中的敏感字段或私有源码以外的未授权材料。演示文章为原创课程数据；官网视觉素材仅在用户确认许可后本地化，来源记录见 `docs/12_北交大官网素材来源与许可.md`。

## 5. 人工责任

AI 输出不是验收结论。学生负责审阅设计、确认业务规则、运行自动化测试、验证权限和数据库对象、检查浏览器页面、核对文档事实并在答辩中解释实现与取舍。作者和审核人信息统一填写“学生填写”，不由 AI 编造。
