# CMS 系统部署说明书

## 1. 运行架构

系统在 Windows 下使用以下组件：

- Python 3.12 与 Django 5.2
- Waitress：8 个工作线程，仅监听 `127.0.0.1:8000`
- MySQL：正式业务数据库
- Redis：首页/文章缓存、公开访问限流和 Admin 登录失败限流
- WhiteNoise：静态文件压缩与缓存
- cpolar：公网模式的随机 HTTPS 隧道

正式运行不会静默回退到 SQLite。SQLite 只允许开发者显式设置 `DB_ENGINE=sqlite` 后用于本地调试。

Docker Compose 是独立的集成运行方式：Web 容器通过内部服务名访问 `db:3306` 与 `redis:6379`，只有 `127.0.0.1:8000` 发布到宿主机。Redis 保存可重建的缓存和限流状态，不挂载持久卷；MySQL 使用命名卷保存业务数据。

## 2. 安装

在 `cms_site` 目录创建虚拟环境并安装运行依赖：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\activate
python -m pip install -r requirements.txt
```

安装并启动 MySQL、Redis。创建 MySQL 数据库与独立用户，数据库字符集使用 `utf8mb4`。

## 3. 环境变量

本地与公网模式都需要：

```bat
set DB_ENGINE=mysql
set DB_NAME=cms
set DB_USER=cms_user
set DB_PASSWORD=你的数据库密码
set DB_HOST=127.0.0.1
set DB_PORT=3306
set REDIS_URL=redis://127.0.0.1:6379/0
```

公网模式还必须设置足够长的随机密钥：

```bat
set DJANGO_SECRET_KEY=使用密码生成器创建的随机长密钥
```

这些变量只保存在本机用户环境或当前命令行会话中，不得写进仓库或 BAT。

## 4. 本地启动

双击项目根目录的 `启动系统.bat`。脚本会依次：

1. 检查虚拟环境、MySQL 和缓存配置；
2. 执行数据库迁移；
3. 幂等初始化演示数据；
4. 收集静态文件；
5. 使用 Waitress 启动 `http://127.0.0.1:8000/`。

脚本任一步失败都会返回非零退出码，不会继续启动不完整服务。

## 5. 公网启动

1. 安装 cpolar；
2. 在命令行手动执行一次 `cpolar authtoken <你的令牌>`；
3. 设置第 3 节全部环境变量；
4. 双击 `启动公网系统.bat`。

公网脚本不会读取或保存 token。Python 启动器会：

- 建立一次性 cpolar HTTPS 隧道；
- 严格校验随机域名属于 cpolar；
- 只在本次子进程环境中注入 `ALLOWED_HOSTS` 与 CSRF 来源；
- 关闭 DEBUG，启用安全 Cookie、HTTPS 重定向和 HSTS；
- 完成部署检查、迁移、静态收集和依赖健康检查；
- 输出并打开本次公网 HTTPS 地址；
- 退出时只清理本次创建的 cpolar 和 Waitress 子进程。

免费随机域名可能变化，每次公网演示都应重新运行公网 BAT。

## 6. 管理账号

首次部署使用以下命令创建管理员：

```powershell
python manage.py createsuperuser
```

必须使用非默认用户名和强密码。仓库不提供公开默认账号或密码。

## 7. 健康检查与故障

- `/health/live/`：确认 Web 进程存活；
- `/health/ready/`：确认数据库和缓存可用；
- MySQL 不可用：启动失败；
- 公网模式 Redis 不可用：启动失败，Admin 登录限流不会失效；
- cpolar 无法认证或超时：公网启动失败并清理本次子进程；
- 端口 8000 被占用：先停止占用进程，再重新启动。

系统提供独立的 400、403、404、429 和 500 错误页，公网响应不会显示堆栈、SQL、凭据或本机路径。

## 8. Docker Compose 启动

安装 Docker Desktop 或 Docker Engine，在仓库根目录创建本地环境文件：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，分别设置 MySQL 普通用户密码、MySQL root 密码和 Django 密钥。三个值必须不同，`.env` 已被 Git 忽略，不得提交。

启动并等待所有长期服务健康：

```powershell
docker compose up --build --wait
docker compose ps
```

服务启动顺序为：MySQL/Redis 健康 → `migrate` 执行迁移与演示数据初始化 → Web 启动。Compose 使用 `DJANGO_MODE=local` 与 `DJANGO_DEBUG=0` 提供本机 HTTP 集成环境；公网 HTTPS 仍通过第 5 节的 cpolar 启动器运行。

查看日志和健康状态：

```powershell
docker compose logs -f web
Invoke-WebRequest http://127.0.0.1:8000/health/live/
Invoke-WebRequest http://127.0.0.1:8000/health/ready/
```

Web、MySQL 与 Redis 日志均限制为每文件 10 MB、最多 3 个文件。`/health/live/` 仅确认 Web 进程响应；`/health/ready/` 会实际检查 MySQL 查询和 Redis 写读闭环。

停止容器但保留 MySQL 数据：

```powershell
docker compose down
```

仅在需要完全重置数据库时使用 `docker compose down -v`；`-v` 会删除 `mysql-data` 命名卷，操作不可恢复。

常见排查命令：

```powershell
docker compose ps
docker compose logs --no-color web migrate db redis
docker compose config
```
