## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `config` | PostgreSQL 配置、路由、WSGI 和安全设置 |
| `content` | Category/Item、查询表单、选择器、公开视图、演示数据、Admin |
| `core` | 缓存、限流、健康检查、结构化日志、日志阅读、管理用户表单 |
| `templates` / `static` | 北交大风格公开界面与克制的 Admin 品牌层 |
| `tests` | 数据库、模型、认证、后台、日志、查询、模板、素材和文档合同 |

## 2. 接口概览

公开接口为 `/`、`/search/`、`/item/<pk>/`；认证接口为 `/accounts/login/` 和退出 POST；管理接口为 `/admin/`、`/admin/system-logs/`；健康接口为 `/health/live/`、`/health/ready/`。所有业务数据通过 Django ORM 访问 PostgreSQL。

## 3. 部署拓扑

Docker Compose 运行 PostgreSQL 18.6、Redis、一次性 `migrate` 服务和 Waitress Web。`migrate` 成功执行迁移、`verify_postgres`、`seed_data`、`collectstatic` 后 Web 才启动。宿主机仅暴露 Web 回环端口；数据库和 Redis 保持在 Compose 网络。

## 4. 质量策略

公开热点由数据库索引、稳定分页与 `select_related` 支撑；请求日志不记录查询串、Cookie、密码或授权头；测试服务使用独立 PostgreSQL 测试数据库并执行 coverage 门禁。完整取舍见 `docs/08_PostgreSQL技术报告.md`。
