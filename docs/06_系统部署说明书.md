# PostgreSQL CMS 系统部署说明书

## 1. 运行前提

标准运行入口为 Docker Compose：PostgreSQL 18.6、Redis 7.4、Django 5.2、Waitress 和 WhiteNoise。数据库与 Redis 仅在容器网络可见，Web 默认绑定 `127.0.0.1:8000`。

## 2. 必需环境变量

| 变量 | 用途 |
| --- | --- |
| `DJANGO_SECRET_KEY` | Django 生产密钥 |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | PostgreSQL 数据库、账户和密码 |
| `POSTGRES_HOST` / `POSTGRES_PORT` | PostgreSQL 连接地址和端口 |
| `DEMO_USER_PASSWORD` | 种子命令读取的普通用户密码；管理员使用固定账号 `CTX` 和密码 `1234` |
| `REDIS_URL` | Redis 地址，Compose 已注入 |

密钥和密码只设置在当前终端或被忽略的本地环境文件，不能提交、写入 BAT 或复制到交付文档。

## 3. Compose 部署

```powershell
$env:DJANGO_SECRET_KEY='随机长密钥'
$env:POSTGRES_PASSWORD='独立数据库密码'
$env:DEMO_USER_PASSWORD='普通演示用户密码'
docker compose up --build --wait
docker compose ps
```

迁移服务顺序为 `migrate --noinput`、`verify_postgres`、`seed_data`、`collectstatic --noinput`。成功后访问首页和 `/admin/`。日志使用 `docker compose logs -f web` 查看。

## 4. 原生 PostgreSQL 部署

创建 PostgreSQL 18.6 数据库与最小权限账户后，在 `cms_site/` 设置 `POSTGRES_*` 环境变量：

```powershell
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py verify_postgres
.\.venv\Scripts\python.exe manage.py seed_data
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe manage.py serve_waitress
```

`verify_postgres` 拒绝非 PostgreSQL 或主版本低于 18 的服务端。

## 5. 运维与故障处理

- `/health/live/` 仅确认 Web 进程；`/health/ready/` 同时检查 PostgreSQL 和 Redis。
- PostgreSQL 不可用时 readiness 为 503；公网模式 Redis 不可用时预检失败。
- `docker compose down` 保留卷；`docker compose down --volumes` 删除 PostgreSQL 数据，执行前必须确认备份与重置意图。
- 使用 `pg_dump` 备份业务库；恢复前在隔离环境演练，并在恢复后运行 `verify_postgres` 与应用检查。

## 6. 安全检查

生产环境配置 `DJANGO_DEBUG=0`、明确主机与 CSRF 来源，运行：

```powershell
.\.venv\Scripts\python.exe manage.py check --deploy
```

该检查补充而不替代人工审查密钥、备份、访问控制和日志脱敏。
