## 1. 引言

### 1.1 编写目的

本文档是"基于 Python/Django 的 CMS 原型系统"项目的需求基线，用于：

- 明确系统**做什么**（功能范围）、**为谁做**（角色）、**做到什么程度**（验收标准）；
- 作为《详细设计文档》《测试文档》以及代码实现的唯一需求输入；
- 支撑 V 模型开发流程：**需求分析（左臂） ↔ 验收测试（右臂）**，保证每个需求可测试、可追踪。

### 1.2 项目背景

内容管理系统（Content Management System，CMS）是一类"管理信息、并将信息对外发布"的软件系统：管理用户在系统后台完成内容（本文档统一称"文章"）的采集与发布，普通用户在前台浏览内容。本作业选取交大官网（www.bjtu.edu.cn）、研究生院官网（gs.bjtu.edu.cn）等真实 CMS 为参照，要求以 **Python + Django** 构建一个可运行的 CMS 原型。

### 1.3 术语与定义

| 术语 | 定义 |
| --- | --- |
| CMS | Content Management System（内容管理系统） |
| 栏目（Category） | 内容的分类目录（如"教学动态""通知公告"），一对多关联文章 |
| 文章（Item） | 系统对外发布的内容单元，至少包含标题、正文、所属栏目、发表时间 |
| 管理用户 | 拥有后台管理权限的用户，可对栏目、文章执行增删改查 |
| 普通用户 | 前台访客，无需登录，可浏览与查询已发布内容 |
| 查询模式 | 前台查询功能支持的三种检索维度：按文章题目、按发表时间、按栏目 |

## 2. 系统总体描述

### 2.1 产品定位

面向课程教学与演示场景的 **CMS 最小可行原型（MVP）**：具备"内容生产—内容管理—内容发布—内容查询"的完整闭环，架构清晰、可解释、可维护、可复现。

### 2.2 系统边界（范围）

**纳入范围：**

1. 两个核心实体：栏目（Category）、文章（Item）；
2. 管理端：栏目与文章的增删改查，发布文章时可选栏目；
3. 前台：文章浏览（列表、详情）、三种模式的查询；
4. 权限：管理用户登录后管理，普通用户免登录浏览；
5. 演示数据、自动化测试、部署文档、Git 持续提交。

**不进范围（迭代阶段可扩展）**：多级栏目树与栏目排序拖拽、富文本在线编辑器、图片/附件桶、评论与点赞、全文搜索引擎、多站点/多主题、开放用户自助注册（账号统一由管理员创建）。

### 2.3 用户角色

| 角色 | 权限 | 使用入口 |
| --- | --- | --- |
| 管理用户（Admin） | 登录后台；栏目/文章全部增删改查；管理账号 | 后台管理界面（计划采用 Django Admin + 可选自定义管理首页） |
| 普通用户（Visitor） | 免登录浏览前台、执行三种模式查询 | 前台页面 |

> 权限模型基于 Django 内置认证：`is_staff = True` 即管理用户；普通用户不要求注册。

### 2.4 技术选型约束（题目规定 + 拟定）

| 项 | 计划方案 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.13 | 框架支持范围内稳定版本 |
| 框架 | Django 5.2 LTS | 官方长期支持至 2028-04，优先可用性与资料完整性 |
| 数据库 | SQLite（默认）/ MySQL（可选部署） | 原型数据量级 SQLite 足够，且零安装 |
| 前端 | Django 模板引擎 + Bootstrap 5 | 服务端渲染，降低复杂度 |
| 版本控制 | Git + GitHub | 必须"持续提交、禁止一次性提交" |
| 代码规范 | PEP 8（用 Ruff/flake8 校准） | 评分硬指标 |

**约束来源**：题目明确指定 = Python 语言、Django 框架"使用……"。如需调整技术栈（如换框架），须在报告中说明调整目的（本方案不调整，仅确定具体版本）。

| 优先级 | 含义 | 需求集合 |

### 3.1 用例图（用文本描述，最终设计阶段可转 UML 图）

       ├──▶ UC-03  文章管理（增/删/改/查）         │

                    ┌─────────────────────────────┐
  普通用户 ────────▶ │ UC-05 浏览前台（栏目列表/文章详情）│
       ├──▶ UC-06  按题目查询                        │

### 3.2 用例规约（关键用例）

**UC-03 发布文章（核心业务主用例）**

| 条目 | 内容 |
| --- | --- |
| 参与者 | 管理用户（已登录） |
| 前置条件 | 系统已启动；数据库存在至少一个栏目；用户已通过后台认证 |
| 主流程 | 1. 用户进入"文章→添加"；2. 系统显示文章表单；3. 用户输入标题、正文，从下拉框选择栏目；4. 用户点击保存；5. 系统校验通过，写入数据库，页面跳转至文章列表，出现新文章 |
| 备选流程 | 3a. 标题为空/超长 → 系统提示"标题必填/请在 200 字以内"，不落库；3b. 未选择栏目 → 提示"请选择栏目"；4a. 数据库异常 → 系统回滚并显示统一错误页，数据不丢失 |
| 后置条件 | 新文章在前台列表与详情页可见 |

**UC-05 前台查询（三种模式）**

| 条目 | 内容 |
| --- | --- |
| 参与者 | 普通用户（未登录） |
| 前置条件 | 系统已启动，存在演示数据 |
| 基本流程 | 用户在前台查询输入：① 输入标题关键词【或】② 输入/选择起止时间【或】③ 选择栏目任一条件；点击[查询]；系统在列表中展示匹配条件的结果集（若同时提供多个条件，按"与"组合），空结果时提示"没有符合条件的文章" |
| 异常流程 | 时间格式非法（如 2026-13-45）→ 表单校验不通过，提示错误，不出现 500；查询字符串超长 → 截断/拒绝；页码越界 → 自动回到末页/首页 |

## 4. 功能需求详述

> 每条需求包含：编号 / 需求名称 / 描述 / 输入 / 输出与行为 / **验收标准（可测试）**。编号全局唯一，贯穿设计、测试、追踪矩阵。

### 4.1 栏目管理（管理端）

| 编号 | 需求名称 | 需求描述 | 验收标准 |
| --- | --- | --- | --- |
| FR-CAT-01 | 新增栏目 | 管理用户可创建栏目，栏目名唯一非空、可填写描述 | 空名称被拒绝；重复名称被拒绝；创建后出现在栏目列表与前台导航 |
| FR-CAT-02 | 修改栏目 | 可修改栏目名称与描述 | 修改后前台与文章关联的栏目显示同步更新 |
| FR-CAT-03 | 删除栏目 | 可删除栏目 | 删除空栏目成功；**删除包含文章的栏目被阻止并提示**（业务规则：保护数据完整性，见设计取舍 D-03） |
| FR-CAT-04 | 查询栏目 | 后台列出全部栏目（支持按名称检索） | 列表显示名称、文章数、建立时间 |

### 4.2 文章管理（管理端）

| 编号 | 需求名称 | 需求描述 | 输入标准 |
| --- | --- | --- | --- |
| FR-ART-01 | 发布（新增）文章 | 录入标题（必填）、正文（必填，可空）、选择栏目（必选）；系统自动记录发表时间与最后更新时间 | 必修项缺失 → 保存失败并提示；保存成功 → 前台立即可见；发表时间自动写入 |
| FR-ART-02 | 修改文章 | 可修改标题、正文、栏目 | 修改后前台显示最新内容与更新时间 |
| FR-ART-03 | 删除文章 | 可删除单篇文章 | 删除后列表/详情均不可见，统计数一致 |
| FR-ART-04 | 查询浏览文章（后台） | 后台列表支持按标题/栏目/时间过滤查看 | 过滤结果正确 |
| FR-ART-05 | 发布状态控制（扩展） | 每篇文章有"发布/草稿"状态，仅"已发布"对前台可见 | 草稿文章前台不可见（体现"发布"语义） |

### 4.3 前台浏览

| 编号 | 需求名称 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| FR-UI-01 | 首页 | 展示全部栏目导航 + 最新 N 篇已发布文章 | 按时间倒序、标题可点击 |
| FR-UI-02 | 栏目文章列表 | 点击栏目进入该栏目文章列表页 | 仅显示该栏目的已发布文章，按时间倒序 |
| FR-UI-03 | 文章详情 | 点击标题进入详情：标题、栏目、发表时间、正文 | 内容正确完整展示；HTML 上页面结构语义正确 |

### 4.4 前台查询（题目核心需求）

| 编号 | 需求名称 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| FR-SRCH-01 | 按文章题目查询 | 输入关键词，模糊匹配标题中含关键词的文章 | 匹配≥1：正确结果集；0 结果：友好提示；关键词前后空格被忽略；大小写不敏感 |
| FR-SRCH-02 | 按发表时间查询 | 输入起始/结束日期（任一），查询该时间段发表的文章 | 起止均可为空；仅起始：查询该日后；仅结束：查询该日前；非法日期报错不崩溃 |
| FR-SRCH-03 | 按栏目查询 | 从下拉框选择栏目，查询该栏目全部文章 | 选项来自真实栏目表；未选择时不做栏目过滤 |
| FR-SRCH-04 | 组合条件查询 | 三个条件可任意组合（"与"逻辑） | 组合条件下结果集 = 各条件结果交集；查询参数不要丢失回显在表单中 |
| FR-PAGE-01 | 分页 | 结果集超过单页数量（暂定 10 条/页）时分页展示 | 页数正确；翻页后条件保持；页码越界（0/负数/超大）不报 500 |

### 4.5 系统支撑

| 编号 | 需求 | 描述与验收标准 |
| --- | --- | --- |
| FR-DEMO-01 | 演示数据 | 提供命令行种子命令或 fixture，一次导入 5 个栏目 + 50+ 篇文章，时间分布覆盖 2023—2026 年，便于演示三种查询 |
| FR-DEMO-02 | 默认账号 | 提供超级管理员默认账号（文档记录），便于助教验收 |
| FR-DEPL-01 | 可复现部署 | 干净环境按《系统部署说明书》步骤可完成：建环境 → 装依赖 → migrate → 导入演示数据 → 启动 → 访问（验收脚本见 6.2） |

## 5. 非功能需求（NFR）

| 编号 | 类别 | 需求描述 | 可度量标准 |
| --- | --- | --- | --- |
| NFR-01 | 输入校验 | 所有用户输入（表单、查询参数、URL 参数）必须验证；非法输入不得引发 500 | 非法输入 100% 被拦截或友好提示；自动化测试含校验用例 |
| NFR-02 | 安全 | 防止 SQL 注入（ORM 参数化）、XSS（模板转义）、CSRF 伪造；管理端权限隔离 | 安全用例通过：注入样例不命中；非管理用户访问管理 URL 被拒绝（重定向登录/403） |
| NFR-03 | 性能 | 常规操作响应（本地环境） | 首页/列表/查询 ≤ 500 ms（本机 ≈10K 条数据）；索引字段合理（publish_time 索引） |
| NFR-04 | 可维护性 | 代码遵循 PEP 8；关键逻辑含中文注释；目录职责清晰；模块间依赖明确 | `ruff check` 无错误；核心模块注释覆盖率达标；设计文档与代码一一对应 |
| NFR-05 | 测试 | 具备基础单元/集成测试，覆盖核心业务流程 | 核心流程（发布→浏览→查询→删除）用例 100% 通过；coverage 对核心模块 ≥ 80% |
| NFR-06 | 版本管理 | Git 持续提交，禁止一次性提交全部代码 | 提交日志 ≥ 8 次且语义分段清晰，可导出日志 |
| NFR-07 | 透明可维护 | 使用 AI 辅助时必须记录模型/环节/提示词/采纳与拒绝理由 | 提交《AI 使用说明》文档 |
| NFR-08 | 可移植（可选） | 数据库可切换 MySQL | settings 提供切换说明文档 |
| NFR-09 | AI 使用合规（对应题目Ⅱ节） | 提交《AI 使用说明》：使用模型/工具、使用环节（需求拆解/编码/调试/测试/文档）、关键提示词示例、采纳与未采纳建议及理由、最终人工核验方式 | 验收核对文档齐全；**不得向外部模型平台上传敏感/真实个人信息**（演示数据不含真实信息） |
| NFR-10 | 引用来源与许可证（对应题目Ⅱ节） | 引用外部代码、模板、教程内容须标注来源与许可证 | 详细设计文档 §17 与部署说明书附录提供引用清单 |

## 6. 验收标准（V 模型右臂：系统级验收测试输入）

### 6.1 验收测试准则

| 准则 | 目标值 |
| --- | --- |
| 功能完整度 | 4.1—4.5 段全部 Must 需求实现 |
| 自动化测试 | `python manage.py test` 全部通过（NFR-05） |
| 部署复现 | 按文档在干净环境一次成功，≤ 20 分钟 |
| 代码规范 | ruff/flake8 静态检查通过 |
| 版本管理 | Git 日志 ≥ 10 条渐进提交 |

### 6.2 助教验收冒烟脚本（概要）

1. 环境安装（见部署说明）→ 2. `migrate` → 3. 导入演示数据 → 4. 创建默认账号 → 5. `runserver` 访问前台：栏目导航、最新文章、查询三种模式分别演示 → 6. 登录后台发布一篇文章 → 前台可见 → 7. 删除文章 → 8. 尝试删除"有文章的栏目"（应被阻）→ 9. 非法日期查询（无 500）→ 10. `python manage.py test`。

> 详细验收用例（输入、前置、步骤、预期）见《测试文档》第 8 章"验收测试"小节。
