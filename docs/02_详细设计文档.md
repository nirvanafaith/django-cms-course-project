## 1. 架构

系统为 Django 服务端渲染单体：`content` 负责栏目、文章、表单、查询器和公开视图；Django `auth` 与 Admin 负责认证、角色和 CRUD；`core` 负责健康检查、缓存、限流、JSONL 日志和后台日志阅读。PostgreSQL 18.6 是唯一业务事实来源，Redis 仅保存可重建状态。

```text
Browser -> middleware -> views -> forms/selectors -> PostgreSQL -> templates
Admin   -> Django Admin -> models -> PostgreSQL / django_admin_log
```

## 2. 数据设计

核心表为 `auth_user`、`content_category`、`content_item`；Django 的权限、会话、内容类型、迁移和管理日志表属于框架支撑表。

- `Category.name` 唯一，文章外键采用 `PROTECT`。
- `Item.title` 与 `Item.content` 在 Admin 表单边界去空白；`is_published` 默认 `False`；作者删除使用 `SET_NULL`。
- 公开排序为 `-publish_time, -pk`。
- 索引：`item_pub_time_idx`、`item_cat_pub_time_idx`、`item_title_trgm_idx`；迁移启用 `pg_trgm`，标题索引为 `UPPER(title)` 的部分 GIN 索引。

## 3. 公开查询

`SearchForm` 将 GET 输入解析为关键词、日期和栏目；非法输入直接返回空 QuerySet 与中文错误。起止日期在 `Asia/Shanghai` 自然日解释且两端包含。查询器统一执行 `published()`、稳定排序和 `select_related`，首页用一条有界文章查询在 Python 中分组，避免按栏目 N+1。

## 4. 认证、后台与日志

普通用户同时为非 staff、非 superuser；管理员同时为 staff、superuser。前台仅根据 `is_superuser` 显示管理入口，Django Admin 再执行服务端授权。用户角色表单同步两枚权限标记。`LogEntry` 为只读审计；系统日志为允许字段的 UTF-8 JSONL，按天轮转 14 天，后台最多读取 5000 条并每页展示 50 条。

## 5. 前端与可访问性

`DESIGN.md` 是设计令牌和响应式规则的单一来源。前端本地加载校名标识和五张官网授权素材，不热链接；`main.js` 提供可暂停、可用方向键控制、尊重减少动态偏好的轮播和移动导航。页面保证唯一 `h1`、skip link、可见焦点与至少 44px 的移动端交互目标。

## 6. 失败处理

数据库不可用时 readiness 返回 503；Redis 不可用时本地公开页可降级为无缓存，公网预检失败关闭。草稿与不存在文章统一 404；日志损坏行跳过，日志页不暴露原始内容。系统不吞没未预期异常。
