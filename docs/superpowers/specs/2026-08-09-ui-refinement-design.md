# CMS 前后台 UI 精修设计规格

## 1. 目标与范围

本次改造将现有 Django CMS 精修为统一的“编辑型内容门户”。视觉借鉴高质量消费级产品常见的精确留白、克制中性色、清晰排版和单一动作色，但不使用 Apple 或其他公司的名称、标识、专有图像、专有字体或品牌文案。

改造范围包括：

- 前台首页、文章列表/搜索结果、文章详情、搜索表单及全局布局；
- 原生 Django Admin 的登录页、首页、列表、表单、筛选、消息和操作控件；
- 桌面、平板和移动端响应式表现；
- 键盘操作、焦点状态、语义结构、错误与空状态等可访问性体验；
- 与视觉改造直接相关的模板测试、浏览器测试和文档更新。

本次不自建后台 CRUD，不引入 React、Vue 或大型前端框架，不改变业务模型、查询语义、URL、数据库结构、权限规则和部署方式。

## 2. 课程要求基线

UI 改造不得削弱或替代以下既有验收能力：

- 使用 Python 与 Django 实现 CMS；
- 保留 `Category` 与 `Item` 两个核心实体；
- 管理用户继续通过 Django Admin 发布文章、选择栏目并完成栏目/文章增删改查；
- 普通用户无需登录即可浏览已发布文章；
- 前台继续支持按题目、按发表时间、按栏目三种查询模式及组合查询；
- 查询条件在分页中保持，错误输入有明确提示且不导致 500；
- 草稿对前台不可见；
- 现有 PEP 8、测试、演示数据、可复现部署、Git 历史和 AI 使用说明要求保持有效；
- 新增代码应体量适中、职责清晰，并能在课程答辩中解释其作用与设计取舍。

## 3. 用户与关键任务

### 3.1 普通访客

普通访客需要在无需学习系统结构的情况下完成：

1. 从首页选择栏目；
2. 浏览最新文章；
3. 按题目、时间或栏目查询文章；
4. 理解当前生效的查询条件；
5. 从空结果或错误状态恢复；
6. 阅读文章并返回所属栏目。

### 3.2 管理用户

管理用户需要继续依赖 Django Admin 完成：

1. 登录后台；
2. 创建、修改、查询和删除栏目；
3. 创建、修改、查询、发布、撤回和删除文章；
4. 使用现有筛选器、搜索、批量操作和删除确认；
5. 明确理解操作反馈、错误和危险操作。

### 3.3 验收人员

助教应能从首页快速识别栏目浏览、最新文章、全部文章和搜索入口，并能按既有验收脚本完成三种查询、后台发布、草稿隔离和 CRUD 检查。

## 4. 设计方向

### 4.1 氛围与识别

界面是一座安静、可信、易读的校园内容门户。识别点是“编辑式节奏”：标题、元数据、正文和操作依靠精确的字号、留白与色阶形成秩序，而不是依赖装饰性插画、渐变或大量卡片。

### 4.2 视觉原则

- 以冷中性白、浅灰和近黑为基础；
- 低饱和蓝仅用于链接、焦点、选中和主要操作；
- 表面优先通过色阶和细边框分层，阴影只用于确有浮层语义的元素；
- 不使用营销式巨型 Hero，不用装饰性渐变、彩色光斑或多种强调色；
- 不使用任何品牌名称、品牌标识、专有图像或品牌相关文字；
- 不使用 emoji 充当图标；需要图标时使用风格统一、可解释的 SVG 图标；
- 卡片只用于栏目入口、表单面板等确有分组意义的内容，避免卡片嵌套。

## 5. 信息架构

### 5.1 全局布局

- 顶部栏包含站点名称、首页、全部文章、搜索，以及仅管理员可见的后台入口；
- 当前页面使用明确的选中状态和 `aria-current="page"`；
- 移动端提供可操作的折叠菜单按钮，按钮包含可访问名称和展开状态；
- 页面顶部提供隐藏的“跳到主要内容”链接；
- 页脚保持简洁，只说明项目性质和课程信息，不形成链接堆叠。

### 5.2 首页

- 首屏为紧凑欢迎区，直接说明“浏览栏目或查找文章”；
- 提供明确的“浏览全部文章”和“搜索文章”入口；
- 栏目导航紧随欢迎区，整个栏目入口可点击，显示栏目名、说明（存在时）和文章数；
- 最新文章以可扫描的文章行展示标题、栏目和发布时间；
- 无栏目或无已发布文章时提供解释性空状态和下一步建议。

### 5.3 列表与搜索

- 列表页和搜索页共用同一结果布局；
- 页面标题区说明当前内容范围，并显示结果数量或当前栏目语境；
- 桌面端查询面板位于左侧，移动端置于结果前；
- 查询表单保留题目关键词、起始日期、结束日期和栏目四个字段；
- 字段提供简短帮助文本，日期格式通过原生日期控件或明确格式提示表达；
- 生效条件以可读摘要展示，但不引入改变查询语义的客户端状态；
- 提供“查询”和“清除条件/查看全部”两条恢复路径；
- 空结果说明未找到匹配内容，并提供清除条件和返回全部文章入口；
- 分页保留现有查询参数，当前页、上一页和下一页状态清晰可辨。

### 5.4 文章详情

- 使用面包屑显示首页、所属栏目和当前文章；
- 内容区采用受控阅读宽度；
- 标题、栏目、发表时间和作者形成清晰元数据层级；
- 正文优先，保持舒展行距并安全换行；
- 页面末尾提供返回所属栏目入口，避免流程死路。

### 5.5 Django Admin

- 保留 Django Admin 的路由、权限、表单、列表、筛选器、批量操作、删除确认和消息机制；
- 通过官方模板覆盖机制定制基础模板、站点标题和静态样式；
- 登录页、后台首页、对象列表和编辑表单共享前台的颜色、排版、圆角和焦点规范；
- 主操作、次操作和危险操作建立明确层级，删除操作使用独立危险色；
- 消息提示区分成功、警告和错误，并保持文本说明；
- 不隐藏原生 Admin 功能，不通过 CSS 改变字段含义或操作顺序；
- 不复制业务逻辑，不创建与 Admin 重复的自定义 CRUD 视图。

## 6. 设计系统要求

实施开始时，必须先在项目根目录创建 `DESIGN.md`，作为视觉实现的单一事实来源。该文件至少包含：

1. 氛围与身份；
2. 色彩角色和 CSS 变量；
3. 字体栈与字号阶梯；
4. 4px 基础间距、内容宽度和断点；
5. 可复用组件、变体和状态；
6. 动效时长、缓动和减少动态策略；
7. 表面与层级策略；
8. 可访问性约束和已接受设计债务。

所有颜色、字号、间距意图、圆角、阴影和动效必须映射到 `DESIGN.md` 中的令牌。Bootstrap 可继续承担网格和基础控件行为，但视觉表现由项目令牌覆盖，不再直接依赖默认 `primary` 蓝色外观。

## 7. 可复用组件

实施前应在 `DESIGN.md` 中定义并通过组件展示页或等价状态夹具验证以下模式：

- 全局导航：桌面、移动折叠、当前页、键盘焦点；
- 页面标题区：标题、说明、主要入口；
- 栏目入口：默认、悬停、按下、焦点、空描述；
- 文章行：默认、长标题、长栏目名、悬停、焦点；
- 元数据组：栏目、日期、作者；
- 搜索字段组：默认、焦点、已填写、错误、禁用；
- 按钮与文本链接：主要、次要、危险、禁用、按下、焦点；
- 条件摘要：无条件、单条件、组合条件；
- 分页：当前页、可用、禁用、键盘焦点；
- 空状态与反馈消息：空内容、无搜索结果、成功、警告、错误；
- Admin 表单与列表：字段、帮助文本、错误、筛选器和批量操作。

## 8. 排版与布局

- 中文正文采用本机优先的高可读系统字体栈，不下载或冒用专有字体；
- 标题主要使用 600 字重，正文主要使用 400 字重，辅助信息使用 400 或 500；
- 正文默认不小于 16px，后台紧凑辅助信息不小于 14px；
- 文章正文行长目标约 55 至 70 个中文字符，行高约 1.75 至 1.9；
- 页面内容宽度受控，桌面端不因超宽屏被无限拉伸；
- 所有间距基于 4px 倍数，重要区段通过留白而非装饰线堆叠建立节奏；
- 长标题、长栏目名、无空格字符串和表单错误必须安全换行。

## 9. 响应式行为

必须在以下宽度验证完整页面和组件状态：

- `375px`：单列布局；导航折叠；查询表单位于结果前；触控目标至少约 44px；主内容无横向滚动；
- `768px`：栏目可采用两列；表单与结果根据可读性选择堆叠或窄侧栏；
- `1280px`：受控内容宽度；列表和搜索使用稳定侧栏布局；文章阅读栏保持窄列。

字体大小不随视口宽度连续缩放。固定格式控件通过网格、最小尺寸和换行规则避免内容变化引发布局跳动。

## 10. 交互与动效

- 动效仅用于菜单展开、按钮反馈、焦点/状态变化和必要的内容过渡；
- 动画只改变 `transform`、`opacity` 或 `filter`，不动画布局属性；
- 按钮按下提供轻微缩放或位移反馈；
- 所有交互元素必须具有悬停、按下和可见键盘焦点状态；
- 遵守 `prefers-reduced-motion`，减少动态时禁用非必要过渡；
- 不添加纯装饰、无法传达状态或操作含义的动画。

## 11. 可访问性

目标为 WCAG 2.2 AA：

- 正文对比度至少 4.5:1，大字至少 3:1；
- 所有功能可用键盘完成，焦点顺序符合视觉顺序；
- 每个表单字段具有显式标签，帮助文本和错误通过语义关联；
- 导航、主内容、侧栏、文章和页脚使用正确语义地标；
- 当前页、展开状态、无效字段和分页状态使用适当 ARIA；
- 不仅依靠颜色表达错误、选中或危险状态；
- 移动端触控目标保持足够尺寸和间距；
- 页面放大至 200% 时核心任务仍可完成。

## 12. 错误、空状态与恢复

- 日期格式错误、起始日期晚于结束日期和关键词过长继续使用服务端表单校验；
- 错误显示在对应字段附近，顶部可提供错误摘要，但不得重复产生矛盾信息；
- 无栏目、无文章和无查询结果采用不同文案，并给出与状态匹配的下一步；
- 后台成功、警告、错误和删除确认沿用 Django 消息与确认机制，仅改善层级和可读性；
- 不增加无法由当前业务契约触发的推测性错误处理。

## 13. 实现边界

预计主要改动位置：

- `cms_site/templates/base.html`；
- `cms_site/templates/content/index.html`；
- `cms_site/templates/content/item_list.html`；
- `cms_site/templates/content/item_detail.html`；
- `cms_site/templates/content/search_form.html`；
- `cms_site/static/css/custom.css`；
- 新增必要的模板片段、Admin 模板覆盖和 Admin 专用静态样式；
- 仅在页面状态或模板上下文确实缺失时，对视图做最小补充；
- 添加与模板语义、关键入口和状态相关的测试；
- 更新操作说明、测试报告、AI 使用说明和外部来源/许可证清单中受影响的部分。

Bootstrap 5 可保留，但应优先本地可复现方案；若继续使用 CDN，必须保留现有依赖说明并验证离线/网络失败对验收的影响。不得为了视觉效果引入新的大型 JavaScript 依赖。

## 14. 验证与完成标准

### 14.1 自动化验证

- `python manage.py test` 全部通过；
- Python 静态检查保持通过；
- 新增测试覆盖首页入口、三种查询模式、组合查询、分页参数保持、空结果、草稿隔离和 Admin 关键入口；
- 不降低现有测试强度，不删除失败测试。

### 14.2 浏览器功能验证

- 首页可进入栏目、全部文章、搜索和文章详情；
- 三种查询模式和组合查询结果正确；
- 错误输入显示友好错误且不产生 500；
- 分页保持条件；
- 管理员可登录并完成 Category/Item CRUD 与发布状态切换；
- 普通访客无法看到草稿；
- 键盘可完成前台查询、分页、文章浏览和后台主要操作。

### 14.3 视觉验证

- 在 `375px`、`768px`、`1280px` 对每个前台页面和 Admin 关键页面截图检查；
- 检查默认、悬停、按下、焦点、错误、空状态和移动菜单；
- 无文本裁切、不可解释重叠、主内容横向滚动或布局跳动；
- 设计系统令牌与实现一致，无未声明颜色、字号或重复组件模式；
- 最终通过 `/visual-qa` 和实现后代码审查；重大实现还需通过 `/review-work`。

### 14.4 完成定义

只有在课程功能未回归、自动化测试通过、三个断点的视觉与交互检查通过、前后台设计一致、文档同步更新且没有未记录的重大可访问性或设计债务时，本次 UI 精修才算完成。

## 15. 已确认决策

- 改造前台与后台；
- 后台采用“美化原生 Django Admin”，不自建 CRUD；
- 采用“编辑型内容门户”设计方向；
- 首页保持内容与查询导向，不制作营销式落地页；
- 保留 Django 模板与 Bootstrap 技术路线；
- 设计灵感仅抽取通用视觉原则，不使用任何 Apple 相关标识和文字；
- 所有最初课程功能、工程质量与学术诚信要求均为不可变基线。
