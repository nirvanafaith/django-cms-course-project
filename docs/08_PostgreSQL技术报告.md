# PostgreSQL CMS 技术报告

## 1. 选型结论

系统采用 PostgreSQL 18.6 作为唯一关系数据库，Django PostgreSQL 后端与 Psycopg 连接。Docker Compose 统一数据库、缓存、迁移、初始化、静态收集与 Web 启动顺序，避免开发、测试和演示使用不同数据库语义。

## 2. 索引与查询性能

`Item` 的公开查询固定先过滤发布状态，再按发表时间和主键稳定排序。`item_pub_time_idx` 支撑首页和全量公开列表，`item_cat_pub_time_idx` 支撑栏目结合发布时间的列表，`item_title_trgm_idx` 通过 `pg_trgm` 和 `UPPER(title)` 的部分 GIN 索引支撑已发布标题包含搜索。性能测试在扩展数据下执行 `ANALYZE` 与 `EXPLAIN`，而不以 36 条演示数据推断索引效果。

## 3. 一致性与并发

栏目外键使用 `PROTECT`，防止删除仍被文章引用的栏目；作者删除使用 `SET_NULL` 保留历史文章。Admin 批量发布、撤回和写操作借助事务提交后的缓存失效，避免事务回滚后提前清理缓存。`seed_data` 以用户名、栏目名、标题和栏目组合为自然键幂等同步。

## 4. 安全与日志

查询通过 Django ORM 参数化，模板默认转义，POST 退出携带 CSRF。管理员必须同时具有 staff 和 superuser 标记；系统日志仅写入允许字段，屏蔽查询串、正文、Cookie、密码和授权头，按天保留 14 天。后台 `LogEntry` 和系统日志均为只读查看界面。

## 5. 已知取舍

- 任一管理员都可管理其他管理员，这是两角色模型的明确风险；管理员操作说明要求二次确认。
- Redis 在本地公开浏览可降级为无缓存；公网模式预检失败关闭，避免绕过登录限流。
- Django Admin 宽表格在移动端允许表格容器内部滚动；这比移除筛选、表单或删除确认更符合管理工作流。
