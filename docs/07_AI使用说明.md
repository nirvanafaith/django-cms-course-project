## 4. 采纳与未采纳的建议记录

| 建议来源 | 建议内容 | 是否采纳 | 理由 |
| --- | --- | --- | --- |
| AI | 使用 CBV（ListView/FormView）实现前台 | **未采纳** | FBV 线性代码更易讲解与维护（对应设计取舍 D-01）；若改 CBV 需额外学习成本，原型阶段收益低 |
| AI | 查询改用 django-filter 库 | **未采纳** | 三条条件逻辑简单，标准库与 ORM 足够；减少依赖，保持可维护（D-02） |
| AI | 选用 MySQL 而非 SQLite | **未采纳** | 原型数据量级 SQLite 足够（D-05）；部署简单更符合"可复现"要求 |
| AI | 前端引入 Vue 实现无刷新搜索 | 本阶段未采纳 | 交互需求简单，衡量服务端渲染 + GET 表单更贴合"原型"定位（D-09）；已记录为后续迭代项 |
| AI | 文章删改成软删除（is_deleted 标志） | 未采纳 | 助教验收时"删除后前台消失"即可满足；软删除增加复杂度，决定硬删除 |
| AI | 封面图使用 Pillow + ImageField | 未采纳 | 超出题目的基础功能（图片非必需），作为扩展方向记录 |
| AI | use ruff 同时做 lint 与 format | 采纳 | 一个依赖替代 flake8+black+isort 三件套（NFR-04） |
| AI | 外键删除策略采用 RESTRICT | **未采纳（裁决为 PROTECT）** | RESTRICT 抛 RestrictedError 与测试预期 ProtectedError 不符；PROTECT 语义相同且异常类型对齐（技术报告 §6.1 裁决 D-3'） |
| AI | 仅测试单选字段路径、忽略 Admin 批量 Action | 未采纳 | 批量发布/撤回是设计 §8 加分项，补 T-ADM-07 用例覆盖（覆盖率 97%→99%） |

> 每一条"采纳/拒绝"后附理由 —— 这是评分点"说明关键设计取舍"的直接证据。

## 6. 遇到的主要问题与解决过程

| 问题 | 处理（实际过程） |
| --- | --- |
| Admin 文章表单 publish_time 必填校验失败（POST 返回 200） | 根因：Admin 使用拆分日期组件（publish_time_0/publish_time_1 两个输入），单字段提交无效；测试改为传拆分字段，T-ADM-02/03 回归锁定 |
| staff 用户无法访问 Admin（403） | 根因：is_staff 不等于拥有模型权限；需显式授予 content 应用 add/change/delete/view 权限；T-ADM-06b 回归锁定 |
| 时间范围查询漏掉 end 当天记录（T-IT-08 失败） | 根因：Django 将 `lte=date` 按当天 00:00 转换；视图改用 `end+1 天` 开区间上界（保持走索引），T-IT-08 回归锁定 |
| naive datetime 运行时警告 | 根因：date 边界直接用于 DateTimeField 过滤；新增 `_aware_midnight()` 显式转换，T-IT-08/09 回归 |
| ChoiceField 返回值类型（空串/字符串） | 空表单 category 返回 `''` 而非 None、合法值返回字符串；`clean_category()`/`clean_q()` 统一清洗，T-FM-01/08c 回归 |
| 插件模型序列故障导致子代理失败 | 背景任务（momuser 审查）持续重试失败：fallback 链指向不存在模型；修改 OhMyOpenCode 全部模型序列为 DeepSeek V4 Flash 官方 API 并验证 |
| 分页参数重复/丢失 | `_request_query()` 排除 page 自身并保留其余参数，T-IT-16 回归锁定 |
