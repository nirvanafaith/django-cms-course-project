# PostgreSQL CMS 核心模块答辩说明

## 1. 为什么只保留 PostgreSQL

数据库后端、Compose、迁移、测试与文档统一使用 PostgreSQL 18.6，避免本地和生产数据类型、索引和查询计划不一致。`verify_postgres` 在启动链路中拒绝低版本或错误后端。

## 2. 为什么公开查询放在 selectors

视图仅编排 HTTP、表单、分页和模板；选择器集中发布状态过滤、稳定排序、关联预取和日期语义。QuerySet 是惰性的，只有遍历、分页或显式求值时才执行 SQL，因此可以安全链式组合条件。

## 3. 搜索如何保证正确

`SearchForm` 是 GET 输入边界：关键词去首尾空白，日期按上海自然日转换，栏目使用真实模型选择项，开始晚于结束或范围超过 366 天时不执行业务查询。合法条件用 ORM filter 以 AND 组合，避免字符串拼接 SQL。

## 4. 为什么要三类索引

首页和列表最常见的是发布状态与时间排序，栏目列表再加入栏目外键，标题检索使用三元组 GIN。性能测试在大数据集下读取 EXPLAIN，证明命名索引而不是仅依据理论说明。

## 5. 权限和日志如何设计

两种可见角色复用 Django 用户标记，管理员必须同步设置 staff 和 superuser。Django `LogEntry` 提供管理审计，JSONL 提供请求和安全事件；后者只允许固定字段并脱敏，日志阅读限制数量和筛选范围。

## 6. 需要主动说明的风险

管理员之间可以相互变更，这是题目限定两角色模型的取舍；生产操作需二次核对。Redis 在公开本地模式可降级，但公网模式必须可用。删除含文章栏目被外键保护，不能通过绕过约束删除。
